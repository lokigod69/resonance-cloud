## Persistence and accounting
- Lens deck identity is a per-user/per-language source key, independent of its display name. Adopt only compatible legacy Lens decks. `save_lens_cards` returns exact outcomes keyed by recap client ID; do not infer per-row results from a count. Hint state is user/language scoped and guarded against late queries.
- Live reservation is allocated/debited atomically once for a ten-minute block. One encrypted client secret is persisted before exposure and reused on HTTP retry/reconnect. No browser connection attestation or browser-triggered refund. Definitive/no-secret failure refunds once; abandoned no-secret blocks settle on reservation lookup or the existing daily maintenance cron. Keep ciphertext/claims inaccessible to authenticated clients. Key rotation can make an existing short-lived reservation unavailable; never silently debit a replacement.
- An ephemeral-token expiry is NOT a trusted socket duration limit. Browser timers cannot enforce provider spend against modified clients. A relay or supported revocation is a separate requirement. Existing xAI model remains `grok-voice-think-fast-1.0`; docs mark it deprecated. No live quality or token-reuse handshake was verified in this session.
- Generation charges have operation IDs, exact plan/permanent buckets and the originating subscription period. Failure transition and refund are atomic/idempotent; worker calls carry the operation captured when work starts. Paid retry creates a new operation. Stale/unfenced old workers cannot refund that newer operation. Expired plan credit stays expired. Admin and worker refunds share accounting. Historical ambiguous rows are never guessed into refunds.
- Checkout has one active user reservation and a durable Stripe customer identity. Reuse or expire a checkout before replacement; provider requests have stable idempotency keys. Subscription event ordering and financial invoice accounting are separate: an older paid invoice still receives its one ledger entry. Same-period active/trialing allowance can be granted, while canceled/expired-period allowance is not resurrected. Refunds of invoices that never restored allowance record their financial reversal without clawing unrelated credits. Ordered subscription status persists both period dates. Keep deployed legacy RPC signatures callable during schema-first rollout.
- Study/game recall attempts commit to IndexedDB before sending. FIFO/current-user queue, stable receipt IDs, acknowledge-then-delete, deadline, account-switch handoff, and bounded server clock correction. Visible retry handles persistence failures/conflicts. Existing direct INSERT remains compatible. IndexedDB eviction/private storage behavior is still a physical-browser test boundary.
